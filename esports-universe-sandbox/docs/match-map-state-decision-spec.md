# LoL 比賽模擬 — 地圖狀態／決策層規格（第一版定案）

> 狀態：已定案；Phase A～F（含死亡／復活）已落地；雪球第二輪與河蟹列為後續  
> 關聯：[`event-driven-match-sim-spec.md`](./event-driven-match-sim-spec.md)、[`match-simulation-engine-report.md`](./match-simulation-engine-report.md)  
> 實作位置：`src/app/shared/sim/`  
> 原則：**不要一次重寫整個引擎**；在現有 TimelineEvent 唯一寫入之上加層

---

## 1. 目標

把比賽從「前期／中期／後期戰力抽樣 + 隨機事件」升級為：

**有地圖位置、資源刷新、轉線條件與戰術意圖的連續過程。**

核心問題引擎必須能回答：

1. 現在幾分鐘？
2. 十名選手各自在哪裡、正在做什麼？
3. 哪些外塔還在？
4. 下一個重要物件何時刷新？
5. 雙方各自想做什麼？
6. 目前條件允不允許這個行動？

經濟、KDA、傷害、物件、時間軸、比賽故事，全部由同一套 TimelineEvent 推導。禁止旁路隨機編造。

## 2. 第一版定案表

| 項目 | 第一版決定 |
|---|---|
| 轉線觸發 | **任一外塔摧毀後開放轉線選項，不強制轉線** |
| 物件系統 | 小龍、虛空幼體、預示者、巴龍、遠古龍、防禦塔、主堡 |

| 位置系統 | 十名選手各自有 `locale`、`task` |
| 狀態系統 | 多種地圖狀態可並存；時間是限制條件，不是唯一階段開關 |
| 結束條件 | 推掉主堡（nexus）；本專案不使用投降結束 |

## 3. 時間系統（2026 標準 Summoner's Rift）

| 資源 | 首次出現 | 後續規則 |
|---|---|---|
| 小兵 | 0:30 | 持續出兵 |
| 河蟹 | 2:55 | 符合重生條件後再出 |
| 小龍 | 5:00 | 擊殺後 5 分鐘重生；第四條可成龍魂 |
| 虛空幼體 | 8:00 | **單場一次** |
| 預示者 | 15:00 | **單場一次** |
| 巴龍 | 20:00 | 擊殺後 6 分鐘重生 |
| 遠古巨龍 | 取得龍魂後 6 分鐘 | 擊殺後 6 分鐘重生 |

### 鍍層

- **不可**再把 14:00 當成所有鍍層收入截止。
- 第一版：鍍層可持續存在，價值隨時間衰減（具體衰減曲線可調，放 `balance.ts`）。

### 時間區間（僅供參考，非硬切）

| 參考區間 | 意義 |
|---|---|
| 0～14 分 | 對線期常見窗口 |
| 10～18 分 | 轉線常見窗口（可與對線重疊） |
| 14～25 分 | 中期運營／資源常見窗口 |
| 25 分以後 | 決勝／攻城常見窗口 |

**規則：** 時間限制「什麼事件允許發生」；地圖狀態與位置狀態決定「現在實際在打什麼」。

## 4. 地圖狀態機（可並存）

| 狀態 | 描述 |
|---|---|
| `laning` | 三路對線、打野刷野／Gank、換血、補刀、塔皮 |
| `transition` | 外塔已開轉線選項；ADC 換線、中路集合、邊線牽制等**可能**發生 |
| `objective` | 圍繞小龍／幼體／預示者／巴龍／遠古的視野與爭奪 |
| `siege` | 邊線兵線、大型增益、高地、兵營、主堡 |

不是固定順序。可因外塔、物件或團戰結果提前轉換，也可同時存在（例如上路仍 `laning`，下半部進入 `objective`）。

### 轉線規則（定案）

1. **任一外塔**（上／中／下）被摧毀 → 隊伍獲得「可轉線」旗標。
2. 系統**不強制**立刻轉線。
3. 隊伍決策依兵線壓力、下一物件時間、陣容、風格決定是否轉線、轉哪一邊。
4. 典型但非唯一結果：
   - 下路外塔掉：ADC／輔助可能轉中
   - 中路外塔掉：中央視野與野區入口易被控
   - 上路外塔掉：上路可能分推，或隊伍重心轉下半

## 5. 位置狀態（每位選手）

### `locale`（粗粒度即可）

`top-lane` | `mid-lane` | `bot-lane` | `blue-jungle` | `red-jungle` | `river` | `baron-pit` | `dragon-pit` | `base` | `highland`

### `task`

| 位置 | 可能 task |
|---|---|
| TOP | 對線、邊線牽制、分推、TP 支援 |
| JG | 刷野、入侵、Gank、物件控制、做視野 |
| MID | 對線、遊走、中路推進、支援物件 |
| ADC | 下路發育、中路收線、邊線收線 |
| SUP | 下路保護、遊走、視野控制、物件佈置 |

第一版不做逐隻小兵格子；用 locale + task + 外塔／物件旗標即可驅動合法事件。

## 6. 隊伍決策

### 物件主要意圖（第一版）

| 意圖 | 意義 |
|---|---|
| `contest` | 爭奪該物件 |
| `trade` | 放棄／弱爭該物件，交換另一側資源（塔、另一物件、兵線） |
| `give-up` | 放棄物件，避免不利交戰 |

### 子戰術（保留擴充，第一版可不實作）

```text
intent: contest
method: direct | fake-start | engage-ambush | vision-first
```

### 決策輸入（評分用）

- 線權／推進壓力
- 視野（簡化為河道／坑口控制分數）
- 打野與關鍵位是否存活
- 陣容團戰／分推傾向（現有 TeamStyleAxes）
- 抵達速度（距離＋存活）
- 物件價值 vs 交換價值
- 是否有人在邊線分推

輸出必須可解釋，供故事使用（為何 contest／trade／give-up）。

## 8. 事件必須改後續條件

例：18:02 摧毀下路外塔，必須同時：

1. 產生 `tower` TimelineEvent  
2. 更新經濟  
3. 更新防禦塔狀態（該路外塔不存在）  
4. 開啟／強化轉線選項  
5. 寫入時間軸  
6. 影響後續決策評分（中路集合、下半視野、下一小龍條件）

禁止：
- 經濟曲線自行隨機抖動
- 戰報另外編造與 timeline 無關的事件

### 詳細時間軸

## 11. 分階段實作（禁止一次重寫）

### Phase A — 地圖狀態骨架

- 外塔／內塔旗標進 MatchState／ObjectiveProgress  
- 十人 `locale` + `task` 初始為對線配置  
- 任一外塔摧毀 → `canRotate = true`（不自動換位）  
- 校正物件時鐘：幼體 8:00、預示者 15:00、巴龍 20:00、龍魂後遠古；鍍層改衰減  
- 現有 combat／income／apply 路徑繼續可用

### Phase B — 決策層（物件三意圖）

- 小龍／幼體／預示者／巴龍／遠古：先選 contest／trade／give-up，再擲成敗  
- 預示者成功可觸發撞塔意圖  
- 決策原因寫入事件 payload 或平行 decision log（仍須能追溯到 timeline）

### Phase C — 轉線真正改站位

- `canRotate` 且決策選擇轉線時，更新 ADC／SUP／MID／TOP 的 locale／task  
- 合法擊殺池依 locale（對線期同路；轉線／資源期依當前位置）  
- 故事改為決策段落＋時間軸

### Phase D — 子戰術與深化

- `fake-start`／`engage-ambush`／`vision-first`  
- 河蟹、更細兵線壓力（若需要）

每階段完成後：跑 invariants、probe、人工看一場故事／時間軸是否自洽。

---

## 12. 驗收標準（第一版完成時）

1. 無投降結束；結束必為 nexus。  
2. 小龍／幼體／預示者／巴龍時間符合上表。  
3. 外塔掉落後出現可轉線條件，但不保證立刻轉線。  
4. 物件行動先有意圖再有結果。  
5. 經濟／KDA／傷害／故事均可追溯到同一 timeline。  
6. 比賽敘事以決策段落為主；詳細時間軸仍可展開。
